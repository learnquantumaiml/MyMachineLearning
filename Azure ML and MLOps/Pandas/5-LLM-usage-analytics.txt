#Turning Messy Nested JSON into a Normal Table (GenAI/LLM usage-analytics pipeline)

- This program is a small GenAI/LLM usage-analytics pipeline: I
   a) It takes nested JSON-style logs from Azure OpenAI or MLflow runs, 
      flattens them into a pandas table, then analyzes token usage and failures. 
   b) It is essentially the first step toward building an LLM observability or cost-monitoring dashboard.

  A lot of real Azure AI output doesn't arrive as a clean table. It arrives as nested JSON, the kind of thing we would get back from an 
  Azure OpenAI batch job log, an MLflow run's parameters and metrics, or a Document Intelligence response. 
  Before we can analyze any of it with the tools, we need to flatten it into rows and columns first. So, we can understand in a better way.

Steps: (High Level)
1) Defines nested log data.
2) Flattens nested JSON. (Converts nested keys to separate columns.
3) Analyzes the flattened data. 
4) Improves column names.

What we can achieve with this?
- This is a strong foundation for a practical Azure GenAIOps observability project. 
  We can also extend it to below ideas:
   a) Track token consumption by model, user, application, environment, or day.
   b) Estimate and monitor LLM cost, especially for Azure OpenAI deployments.
   c) Detect failed or slow inference runs and investigate model/version-specific issues.
   d) Build a Power BI dashboard for GenAI usage, reliability, and cost.
   e) Export cleaned metrics to Azure SQL, Cosmos DB, Azure Monitor, or ADLS.
   f) Add alerting, for example when daily token usage or failure rate exceeds a threshold.
   g) Turn it into a reusable Python module inside your GitHub portfolio.
