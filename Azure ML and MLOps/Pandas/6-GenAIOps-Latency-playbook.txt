#GenAIOps-Latency-playbook (GenAIOps reference implementation)

- This program simulates and analyzes minute-by-minute latency telemetry for a deployed ML model endpoint, then demonstrates
  three common monitoring patterns:
  a) Time-bucket aggregation (resample).
  b) Noise-smoothing (rolling window).
  c) Threshold-based alerting.

  Let's see what this program exactly trying to do:

 - Simulates monitoring data: 
   It generates 180 minutes of synthetic latency logs centered around 250 ms with realistic noise, then injects an artificial “slow patch” 
   between minutes 100–120 to mimic an incident.

- Resamples to hourly averages: 
  Uses df.resample("h").mean() to collapse minute-level rows into hourly buckets, giving a higher-level view of performance trends.

- Computes a rolling 15-minute average: 
  Adds a rolling_15min_avg column that smooths short-term noise while preserving the original time resolution, useful for spotting 
  sustained degradations rather than one-off spikes.

- Flags threshold breaches:
  Counts and lists minutes where latency exceeds a fixed SLA threshold (default 350 ms), a simple but practical anomaly-detection 
  pattern for alerting.

  So, what can we achieve from this:
  - This program is a compact, realistic template for building an ML endpoint monitoring and alerting prototype. 
    Specifically, when we can do below things.
    
 a) Validate monitoring logic: 
    Test how resampling, rolling averages, and thresholds behave on data that looks like real telemetry before wiring them 
    into Azure Monitor, Log Analytics, or a custom dashboard.

 b) Tune alert thresholds: 
    Experiment with different threshold values and window sizes (e.g., 15-min vs 30-min rolling) to balance sensitivity (catching 
    real incidents) vs noise (avoiding alert fatigue).

 c) Prototype GenAIOps/MLOps dashboards: 
    Extend this pattern to pull real latency metrics from Azure Application Insights or Azure ML endpoints, 
    then visualize raw, resampled, and rolling metrics side-by-side in a notebook or Streamlit app for your GitHub portfolio.

 5) Demonstrate incident analysis:
    The injected slow patch lets you show how a monitoring system would detect, highlight, and potentially trigger alerts 
    for a degradation window—great for case-study-style READMEs or presentation slides.
