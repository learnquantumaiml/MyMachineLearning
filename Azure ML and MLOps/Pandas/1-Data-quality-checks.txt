##Catching Bad Data Before It Breaks the Model

Every machine learning pipeline, whether it's a simple scikit-learn script or a full Azure ML training job, starts with
the same question: can we trust the data going in? Before any model training, Feature Store write, or AutoML run, someone has to 
check for missing values, duplicate rows, wrong data types, and numbers that don't make sense. That someone is usually pandas.

- This program is a data-quality audit and cleanup pipeline for a small loan‑application dataset, written in Python with pandas and numpy. 
- It’s designed to show, step by step, how to detect and handle common data issues before feeding data into a credit‑risk model or
  any ML pipeline.

What we can achieve from this?
 - Catch bad data before training a model, so our model learns from clean, realistic data.
 - Turn the checks into a reusable step in an ML pipeline (e.g., in Azure ML / MLOps).
 - Create basic data-quality metrics (missing counts, percentages) to monitor over time.
 - Support fair and responsible AI by ensuring only valid, well-checked data is used for decisions like credit risk.

Example:
 - one applicant's age accidentally gets typed out as "forty-one" instead of the number 41, while someone else's age somehow shows up as 190.
 - This script cleans all that messy data right up. It turns word-based ages into missing values, flags unrealistic numbers like 190 as invalid, 
   clears out duplicate applications, and we know how many income details are missing.  
 - That way, we can easily fix or toss out those bad rows before we even touch wer credit-risk model.
