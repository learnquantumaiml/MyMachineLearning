## Classification + Evaluation Metrics (Accuracy, Precision, Recall, F1, ROC-AUC).

I have tried to use this code, that creates a fake loan dataset where only 25% of applicants default. It then also do below steps:

- Trains a Random Forest model to predict whether an applicant will default.
- Compares it with a basic model that always predicts “no default.”
- Measures performance using accuracy, precision, recall, F1, ROC-AUC, and a confusion matrix.

What we can achieve from this?
- How many risky applicants the model correctly identifies?
- How many good customers are incorrectly flagged?
- How many real defaulters the model misses?
- Whether the model is genuinely useful or only has high accuracy because most applicants do not default.

The main lesson of why I used this is, for imbalanced data, accuracy alone can be misleading. 
So, this example helps choose the right metric—for example, prioritize recall if missing a defaulter is very costly.

WHICH METRIC MATTERS MOST? It depends on the business cost:
- Missing a real defaulter (false negative) costs the bank real money
  -> in that case, RECALL matters more than precision.
- Wrongly flagging good customers (false positive) annoys/loses them
  -> in that case, PRECISION matters more than recall.
There is no single 'best' metric — you pick based on which mistake hurts more.
